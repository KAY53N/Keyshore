# Keyshore

非托管钱包练手项目。用古法编程把钱包该有的能力从头写一遍：密钥只在本地生成、加密、签名，服务端不持有助记词、私钥或密码。

**古法编程**在这里指：可以参考 AI 给出的代码，但仓库里的实现必须自己写、自己改，不靠 AI 直接生成或修改代码。

当前仓库刚起步，实现按下面四个阶段推进。

## 原则

- 助记词和私钥只存在本机，加密后落盘，不以明文出设备。
- 未备份或未解锁，不能签名、不能转账、不能兑换、不能连 DApp。
- 密码错误不得解锁；超时自动锁定。
- 默认走测试网；主网必须用户手动开启。
- 转账、兑换、连接、签名、发交易都要先确认再执行。

## 阶段 1｜钱包

把「一串密钥」变成可用、可锁、可恢复的钱包。

- [ ] 打开插件弹窗
- [ ] 创建钱包
- [ ] 生成并显示助记词
- [ ] 校验助记词已备份
- [ ] 导入已有钱包
- [ ] 派生地址
- [ ] 设置密码
- [ ] 加密保存钱包
- [ ] 解锁 / 锁定
- [ ] 密码错误无法解锁
- [ ] 未备份或未解锁不能使用
- [ ] 超时自动锁定
- [ ] 恢复后地址一致

完成标准：同一套助记词，导入后派生出的地址与创建时一致；错误密码解不开；锁住后任何敏感操作都被拒绝。

## 阶段 2｜资产和转账

在已解锁的钱包上读余额、切网络、发交易。

- [ ] 显示钱包名和当前网络
- [ ] 切换网络
- [ ] 添加自定义网络
- [ ] 显示地址、复制地址、收款码
- [ ] 显示 ETH 和代币余额
- [ ] 添加自定义代币
- [ ] 刷新余额
- [ ] 转 ETH
- [ ] 转代币
- [ ] 转账前确认
- [ ] 显示交易哈希和交易状态
- [ ] 默认测试网，主网需手动开启

完成标准：切网后余额和浏览器对应；转账弹出确认页，发出后能跟到哈希和成功 / 失败状态。

## 阶段 3｜兑换

同链和跨链兑换，报价在本地确认，交易由钱包签名后发出。

- [ ] 选择网络、支付代币、获得代币
- [ ] 输入兑换数量
- [ ] 显示报价、滑点、手续费
- [ ] 同链兑换
- [ ] 跨链兑换
- [ ] 显示预计到账时间
- [ ] 授权代币额度
- [ ] 确认后本地签名并发送
- [ ] 显示源链和目标链状态
- [ ] 失败或退回时给出状态
- [ ] 完成后刷新余额

完成标准：授权和兑换都走确认；跨链能分别看到源链、目标链进度；失败或退回有明确状态，成功后余额更新。

## 阶段 4｜DApp

网页 DApp 通过标准连接协议使用本钱包，每一次授权都由用户点头。

- [ ] 连接网页 DApp
- [ ] 批准或拒绝连接
- [ ] 批准或拒绝签名
- [ ] 批准或拒绝交易
- [ ] 断开连接

完成标准：未连接不能签名；拒绝后 DApp 收到拒绝；断开后会话失效，需重新连接。

## 开发

```bash
go run .
```

Go 1.26。实现会按阶段往这个模块里加，而不是先堆一层空壳。
